70B MoE on 24 GB VRAM: What the Sources Actually Support

Deep research report · sources restricted to the supplied package · April 2026

Executive summary

A 70B mixture-of-experts model can be made to start on a 24 GB card, but the supplied sources do not contain a direct 70B-on-24-GB measurement. They do establish the three constraints that decide whether it runs well: the load surface exposed by the server, the cost of speculative decoding, and the size of the quantized weights plus KV cache. The honest conclusion is conditional: a 70B MoE can run if most experts are streamed from system RAM and the context is kept small, but it will not be fast, and the Q3-versus-Q4 speed dispute cannot be settled from the supplied evidence alone. [primary_official] [technical_secondary]

What the serving stack exposes

The primary source lists the LM Studio REST load parameters: context_length, flash_attention, offload_kv_cache_to_gpu, eval_batch_size, physical_batch_size, parallel, context_checkpoints, num_experts and speculative_draft_max_tokens. Unknown keys are rejected with HTTP 400 before the model is loaded. [primary_official] This matters for a 70B MoE because num_experts and the KV-cache placement are the two levers that decide whether the model fits at all.

The source does not state the memory cost of each parameter, nor does it give a formula for a 70B model on a 24 GB card. Those numbers are not provided; this report does not invent them. [primary_official]

Speculative decoding and throughput

The technical secondary source reports that llama.cpp exposes speculative decoding through --spec-type draft-mtp and the MTP head shipped with Qwen3.8 models. On a dense 27B at Q4_K_M, the acceptance rate of three drafts was about 73 percent, and decode throughput rose from 31.2 to 40.3 tokens per second on a V100. [technical_secondary]

That is evidence that MTP can deliver a meaningful speedup when the draft acceptance rate is high. It is not evidence about a 70B MoE: the source measures a dense 27B, on a different GPU, with a different memory hierarchy. Extrapolating the 29 percent gain to a 70B MoE is an assumption, not a measurement. [technical_secondary]

The outdated capacity claim

An older guide states that a 27B Q4_K_M model needs 17.5 GB of VRAM and therefore cannot run on consumer cards at all. [outdated_source] The same source is explicitly described as predating 3-bit quants and KV cache quantization. Its conclusion is therefore a historical statement, not a current constraint. It should not be used to rule out a 70B MoE today, but it also cannot be used to prove that one fits. [outdated_source]

Conflicting claims: Q3 versus Q4

The conflicting source contains two opposed community claims. One says Q3_K_M is faster because the model is smaller; the other says Q4_K_M is faster because Q3 needs more dequantization work. Both were measured on Apple Silicon, where the Q3 kernel is described as unusually slow. [conflicting_source]

Resolution: the two claims are not universal. They are hardware- and kernel-specific. On a CUDA GPU the dequantization cost profile is different from Apple Silicon, so neither claim can be transferred without a local measurement. The defensible procedure is to benchmark both quants on the target machine at the same context and batch size, then keep the faster one that still passes the quality gate. [conflicting_source] [technical_secondary]

What a 24 GB budget implies

A 70B MoE at a 3-bit or 4-bit quantization is larger than 24 GB in weights alone for the configurations described by the sources; the exact file size is not stated in the package. [primary_official] [outdated_source] The practical consequence is that a substantial part of the experts must live in system RAM, and the KV cache should be kept off the GPU with offload_kv_cache_to_gpu=false. [primary_official]

With parallel=1 and small evaluation and physical batches, the GPU is asked to hold fewer activations at once. That reduces peak VRAM at the cost of throughput. The primary source exposes all three knobs, but it does not quantify the trade-off. [primary_official]

Limitations and uncertainty

  • The package contains no direct 70B-on-24-GB benchmark. The fit conclusion is an inference from the exposed parameters, not a measurement. [primary_official]
  • The MTP speedup was measured on a dense 27B on a V100, not on a 70B MoE on consumer hardware. [technical_secondary]
  • The Q3/Q4 conflict is explicitly tied to Apple Silicon; it is not stated whether the result holds on CUDA. [conflicting_source]
  • The outdated guide predates 3-bit quants and KV quantization and should not be treated as a current limit. [outdated_source]
  • The package does not state the exact quantized file size of a 70B MoE, so the amount of RAM offload cannot be calculated from these sources. [primary_official]
